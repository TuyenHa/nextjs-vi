The Original Next.js Router

Pages Router

Tổng hợp đầy đủ tiếng Việt về Pages Router — router cổ điển của Next.js với pages/ directory, getStaticProps, getServerSideProps, và API Routes. Vẫn được support trong Next.js 16+ nhưng khuyến nghị migrate sang App Router cho dự án mới.

Phiên bản16.x (tương thích) Directorypages/ ReactTheo package.json Nguồnnextjs.org/docs/pages
⚠

Đây là router gốc của Next.js. Next.js vẫn tiếp tục hỗ trợ Pages Router trong các phiên bản mới, nhưng team Next.js khuyến nghị migrate sang App Router cho dự án mới để dùng được Server Components và các tính năng React 19. Dự án hiện tại vẫn có thể dùng Pages Router bình thường.

Chương 01

Cài đặt

Tạo project Pages Router bằng CLI với flag --no-app (hoặc chọn "No" khi hỏi App Router trong setup tương tác):

# npm
npx create-next-app@latest my-app --no-app
cd my-app
npm run dev

# pnpm
pnpm create next-app my-app --no-app
cd my-app
pnpm dev

Yêu cầu hệ thống

  • Node.js: tối thiểu 20.9
  • OS: macOS, Windows (gồm WSL), Linux
  • Trình duyệt: Chrome 111+, Edge 111+, Firefox 111+, Safari 16.4+

Cài đặt thủ công

npm i next@latest react@latest react-dom@latest
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "lint": "eslint"
  }
}

Tạo pages directory

Pages Router dùng thư mục pages/ (khác với App Router dùng app/). Tạo file đầu tiên:

// pages/index.tsx — route "/"
export default function Home() {
  return <h1>Hello, Next.js!</h1>
}
So sánh với App Router

Pages Router dùng React phiên bản khai báo trong package.json của bạn — không auto-upgrade như App Router. Điều này đảm bảo tương thích ngược cho các ứng dụng Pages Router hiện có.

Chương 02

Cấu trúc dự án

Mỗi file trong pages/ tự động trở thành 1 route dựa trên tên file. Cấu trúc điển hình:

pages/ _app.tsx # Custom App — layout toàn cục _document.tsx # Custom Document — HTML gốc _error.tsx # Custom error page 404.tsx # Custom 404 500.tsx # Custom 500 index.tsx # / about.tsx # /about blog/ index.tsx # /blog [slug].tsx # /blog/:slug — dynamic api/ hello.ts # /api/hello — API route posts/ [id].ts # /api/posts/:id public/ # Static assets styles/ # Global CSS (tùy chọn) next.config.js

File đặc biệt trong pages/

FileVai trò
_app.tsxOverride App component — wrap toàn bộ pages, áp layout chung, import global CSS
_document.tsxOverride <html> và <body> — chạy 1 lần trên server
_error.tsxCustom error page thay cho trang lỗi mặc định
404.tsxPage riêng cho lỗi 404 (static)
500.tsxPage riêng cho lỗi 500 (static)
api/*API endpoints — server-only, không gửi xuống client bundle

Quy ước tên folder

[param] [...param] [[...param]]
  • pages/posts/[id].js → /posts/1, /posts/abc — Dynamic segment
  • pages/shop/[...slug].js → /shop/a, /shop/a/b/c — Catch-all
  • pages/shop/[[...slug]].js → cả /shop lẫn /shop/a/b — Optional catch-all
Chương 03

Pages & Layouts

Trong Pages Router, không có file layout.tsx đặc biệt như App Router. Layout được implement bằng React components thông thường.

Single layout với Custom App

Nếu cả app dùng 1 layout duy nhất, bọc nó trong _app.tsx:

// pages/_app.tsx
import type { AppProps } from 'next/app'
import Layout from '../components/layout'

export default function MyApp({ Component, pageProps }: AppProps) {
  return (
    <Layout>
      <Component {...pageProps} />
    </Layout>
  )
}

Per-page layouts

Nếu cần layout khác nhau cho mỗi page (vd: dashboard khác marketing), dùng pattern getLayout:

// pages/_app.tsx
import type { ReactElement, ReactNode } from 'react'
import type { NextPage } from 'next'
import type { AppProps } from 'next/app'

export type NextPageWithLayout<P = {}> = NextPage<P> & {
  getLayout?: (page: ReactElement) => ReactNode
}

type AppPropsWithLayout = AppProps & {
  Component: NextPageWithLayout
}

export default function MyApp({ Component, pageProps }: AppPropsWithLayout) {
  // Nếu page có getLayout, dùng nó; không thì trả về page trần
  const getLayout = Component.getLayout ?? ((page) => page)
  return getLayout(<Component {...pageProps} />)
}
// pages/dashboard.tsx
import DashboardLayout from '@/components/dashboard-layout'
import type { NextPageWithLayout } from './_app'

const Page: NextPageWithLayout = () => <p>Dashboard</p>

Page.getLayout = (page) => <DashboardLayout>{page}</DashboardLayout>

export default Page
Vì sao dùng getLayout?

Pattern này bảo toàn state giữa các page transitions (input values, scroll position...). React tree được maintain xuyên suốt, cho trải nghiệm SPA thật sự.

Chương 04

Dynamic Routes

Dynamic segments được bọc trong ngoặc vuông ở tên file. Giá trị được truyền qua router.query hoặc context.params (trong data fetching).

Single dynamic segment

// pages/posts/[id].tsx
import { useRouter } from 'next/router'

export default function Post() {
  const router = useRouter()
  const { id } = router.query
  return <p>Post: {id}</p>
}

Catch-all segments

// pages/shop/[...slug].tsx → /shop/a/b/c
// router.query.slug = ['a', 'b', 'c']

Optional catch-all

// pages/shop/[[...slug]].tsx
// - /shop         → slug = undefined
// - /shop/a       → slug = ['a']
// - /shop/a/b/c   → slug = ['a', 'b', 'c']

Thứ tự ưu tiên route

  1. Predefined routes (pages/posts/create.js)
  2. Dynamic routes (pages/posts/[id].js)
  3. Catch-all routes (pages/posts/[...slug].js)
Chương 05

Linking & Navigating

Dùng <Link> từ next/link cho client-side transitions. Next.js tự prefetch các link trong viewport.

<Link> component

import Link from 'next/link'

export default function Home() {
  return (
    <ul>
      <li><Link href="/">Home</Link></li>
      <li><Link href="/about">About</Link></li>
      <li><Link href="/blog/hello-world">Post</Link></li>
    </ul>
  )
}

Programmatic navigation với useRouter

import { useRouter } from 'next/router'

export default function ReadMore() {
  const router = useRouter()
  return (
    <button onClick={() => router.push('/about')}>
      Read more
    </button>
  )
}

Dynamic href

<Link href={`/posts/${post.slug}`}>{post.title}</Link>

Shallow routing

Thay đổi URL mà không chạy lại data fetching (getStaticProps/getServerSideProps):

router.push('/?counter=10', undefined, { shallow: true })

Shallow routing chỉ hoạt động khi URL thay đổi trong cùng 1 page.

So sánh với App Router

App Router import useRouter từ next/navigation. Pages Router import từ next/router — API khác nhau, không thể swap trực tiếp.

Chương 06

Custom App (_app)

File pages/_app.tsx override App component mặc định của Next.js — nơi bạn có thể:

  • Áp layout chung cho mọi page
  • Inject global CSS (đây là nơi duy nhất được phép import global stylesheet)
  • Khởi tạo context providers (Redux, Theme, Auth...)
  • Thêm dữ liệu/hàm chung cho tất cả page
  • Thêm error handling chung

Ví dụ đầy đủ

// pages/_app.tsx
import type { AppProps } from 'next/app'
import '../styles/globals.css'  // Global CSS chỉ được import ở đây

export default function MyApp({ Component, pageProps }: AppProps) {
  return <Component {...pageProps} />
}
Giới hạn

File _app.tsx không hỗ trợ getStaticProps hoặc getServerSideProps. Nếu cần data chung, dùng getInitialProps (opt-out static optimization) hoặc fetch client-side.

Chương 07

Custom Document (_document)

File pages/_document.tsx override thẻ <html> và <body>. Chỉ render 1 lần trên server — không chạy trên client, không re-render.

Use case chính

  • Thêm attribute vào thẻ <html> (vd: lang, dir)
  • Thêm font link, custom script tag trước khi app hydrate
  • Support CSS-in-JS libraries với SSR (styled-components, emotion cũ)
// pages/_document.tsx
import { Html, Head, Main, NextScript } from 'next/document'

export default function Document() {
  return (
    <Html lang="vi">
      <Head>
        <link rel="preconnect" href="https://fonts.googleapis.com" />
      </Head>
      <body>
        <Main />         {/* Nơi React render app */}
        <NextScript />   {/* Script của Next.js */}
      </body>
    </Html>
  )
}
Đừng nhầm

React components ngoài <Main /> không được khởi tạo trên browser. Đừng đặt application logic ở đây — nếu cần component dùng chung thì đặt trong _app.tsx hoặc Layout component.

Chương 08

Rendering Strategies

Pages Router có 4 chiến lược render. Mỗi page có thể chọn 1 chiến lược độc lập:

Chiến lượcKhi nào chạyCách opt-in
SSG (Static Site Generation)Build timeExport getStaticProps
ISR (Incremental Static Regeneration)Build time + revalidate runtimegetStaticProps + revalidate
SSR (Server-Side Rendering)Mỗi requestExport getServerSideProps
CSR (Client-Side Rendering)Trình duyệtKhông export gì, fetch trong useEffect

Automatic Static Optimization

Nếu page không export getServerSideProps hay getStaticProps, Next.js sẽ tự động prerender thành HTML tĩnh ở build time. Đây là mặc định — nhanh nhất và rẻ nhất.

Chương 09

getStaticProps (SSG)

Chạy ở build time trên server. Prerender HTML với data đã fetch sẵn. Phù hợp cho blog, tài liệu, product pages — data không đổi thường xuyên.

// pages/blog/index.tsx
import type { InferGetStaticPropsType, GetStaticProps } from 'next'

type Post = { id: string; title: string }

export const getStaticProps = (async () => {
  const res = await fetch('https://api.example.com/posts')
  const posts: Post[] = await res.json()
  return { props: { posts } }
}) satisfies GetStaticProps<{ posts: Post[] }>

export default function Blog({
  posts,
}: InferGetStaticPropsType<typeof getStaticProps>) {
  return (
    <ul>
      {posts.map((p) => <li key={p.id}>{p.title}</li>)}
    </ul>
  )
}

Incremental Static Regeneration (ISR)

Thêm revalidate để Next.js regenerate page sau N giây:

export async function getStaticProps() {
  const posts = await fetch(...).then((r) => r.json())
  return {
    props: { posts },
    revalidate: 60, // Tái tạo tối đa mỗi 60s khi có request
  }
}
Đặc điểm

getStaticProps không có access vào request (query params, headers). Nếu cần request-time data, dùng getServerSideProps. Trong development (next dev), getStaticProps được gọi mỗi request để dễ debug.

Client-side navigation

Khi page được prerender, Next.js tạo thêm file JSON. Khi navigate bằng <Link>, client chỉ fetch JSON (không chạy lại getStaticProps). Điều này làm navigation cực nhanh.

Chương 10

getStaticPaths

Dùng với dynamic routes ([id].tsx) để Next.js biết cần prerender những path nào ở build time.

// pages/posts/[id].tsx
import type { GetStaticPaths, GetStaticProps } from 'next'

export const getStaticPaths: GetStaticPaths = async () => {
  const posts = await fetch('/api/posts').then((r) => r.json())
  return {
    paths: posts.map((p: any) => ({ params: { id: p.id } })),
    fallback: false, // path không khớp → 404
  }
}

export const getStaticProps: GetStaticProps = async ({ params }) => {
  const post = await fetch(`/api/posts/${params?.id}`).then((r) => r.json())
  return { props: { post } }
}

export default function Post({ post }) {
  return <article><h1>{post.title}</h1></article>
}

Chế độ fallback

Giá trịHành vi
falsePath không trong paths → 404
truePath mới sẽ được render on-demand lần đầu, hiển thị fallback UI trong khi render
'blocking'SSR lần đầu (không fallback UI), sau đó cache như static
Fallback UI

Khi fallback: true, dùng router.isFallback để hiển thị loading state:

const router = useRouter()
if (router.isFallback) return <div>Loading...</div>
Chương 11

getServerSideProps (SSR)

Chạy mỗi request trên server. Phù hợp khi cần data tươi tuyệt đối hoặc phụ thuộc vào request (cookies, headers, query params).

import type { InferGetServerSidePropsType, GetServerSideProps } from 'next'

type Repo = { name: string; stargazers_count: number }

export const getServerSideProps = (async () => {
  const res = await fetch('https://api.github.com/repos/vercel/next.js')
  const repo: Repo = await res.json()
  return { props: { repo } }
}) satisfies GetServerSideProps<{ repo: Repo }>

export default function Page({
  repo,
}: InferGetServerSidePropsType<typeof getServerSideProps>) {
  return <p>Stars: {repo.stargazers_count}</p>
}

Các kết quả trả về

  • { props } — Pass data xuống page
  • { notFound: true } — Trả về trang 404
  • { redirect: { destination, permanent } } — Redirect
export async function getServerSideProps(context) {
  const data = await fetch(...).then((r) => r.json())
  if (!data) return { notFound: true }
  if (!data.user) return {
    redirect: { destination: '/login', permanent: false }
  }
  return { props: { data } }
}

Cache-Control header

Có thể thêm cache header thủ công để CDN cache response:

export async function getServerSideProps({ req, res }) {
  res.setHeader(
    'Cache-Control',
    'public, s-maxage=10, stale-while-revalidate=59'
  )
  return { props: {} }
}
Khi nào KHÔNG dùng

Nếu không cần data tại request time, dùng getStaticProps (có thể kèm ISR) — hiệu năng tốt hơn nhiều vì được cache.

Chương 12

Client-side Fetching

Khi data không cần SEO hoặc phụ thuộc vào user (dashboard, user profile...), fetch ở client bằng useEffect hoặc tốt hơn là SWR / TanStack Query.

Với SWR (từ team Next.js)

import useSWR from 'swr'

const fetcher = (url) => fetch(url).then((r) => r.json())

export default function Profile() {
  const { data, error, isLoading } = useSWR('/api/user', fetcher)

  if (error) return <div>Failed to load</div>
  if (isLoading) return <div>Loading...</div>
  return <div>Hello, {data.name}!</div>
}

SWR tự xử lý caching, revalidation khi focus lại tab, refetch theo interval, deduplication...

Với useEffect thuần

import { useState, useEffect } from 'react'

export default function Profile() {
  const [data, setData] = useState(null)
  useEffect(() => {
    fetch('/api/user').then((r) => r.json()).then(setData)
  }, [])
  if (!data) return <p>Loading</p>
  return <p>Hello, {data.name}!</p>
}
Chương 13

API Routes

Bất kỳ file nào trong pages/api/* sẽ được map thành API endpoint tại /api/*. Server-side only — không tính vào client bundle.

Basic API route

// pages/api/hello.ts
import type { NextApiRequest, NextApiResponse } from 'next'

type ResponseData = { message: string }

export default function handler(
  req: NextApiRequest,
  res: NextApiResponse<ResponseData>
) {
  res.status(200).json({ message: 'Hello from Next.js!' })
}

Xử lý nhiều HTTP methods

export default function handler(req: NextApiRequest, res: NextApiResponse) {
  if (req.method === 'POST') {
    // Xử lý POST
    return res.status(201).json({ ok: true })
  }
  if (req.method === 'GET') {
    return res.status(200).json({ data: [] })
  }
  res.setHeader('Allow', ['GET', 'POST'])
  res.status(405).end(`Method ${req.method} Not Allowed`)
}

Dynamic API routes

// pages/api/posts/[id].ts
export default function handler(req, res) {
  const { id } = req.query
  res.json({ post: id })
}

Built-in request helpers

  • req.cookies — Object chứa cookies
  • req.query — Object chứa query string
  • req.body — Body đã parse theo content-type (hoặc null)
Giới hạn

API Routes không dùng được với static export (output: 'export'). CORS mặc định là same-origin — cần tự wrap với CORS helpers nếu muốn cross-origin.

Khuyến nghị từ team Next.js

Nếu dự án đang migrate sang App Router, thay thế API Routes bằng Route Handlers (app/api/route.ts) — API hiện đại hơn, dựa trên Web Request/Response chuẩn.

Chương 14

Custom Errors

Custom 404 — pages/404.tsx

Static — được prerender ở build time:

// pages/404.tsx
export default function Custom404() {
  return <h1>404 - Trang không tồn tại</h1>
}

Custom 500 — pages/500.tsx

// pages/500.tsx
export default function Custom500() {
  return <h1>500 - Lỗi server</h1>
}

Custom _error.tsx — fallback cho mọi lỗi khác

// pages/_error.tsx
function Error({ statusCode }) {
  return (
    <p>
      {statusCode
        ? `Lỗi ${statusCode} trên server`
        : 'Lỗi phía client'}
    </p>
  )
}

Error.getInitialProps = ({ res, err }) => {
  const statusCode = res ? res.statusCode : err ? err.statusCode : 404
  return { statusCode }
}

export default Error

React Error Boundaries

Pages Router không có file error.js đặc biệt như App Router. Để bắt lỗi React trên client, tự tạo Error Boundary class component và wrap trong _app.tsx.

Images & Fonts

Pages Router dùng chung next/image và next/font với App Router — API hầu hết giống nhau.

next/image

import Image from 'next/image'

export default function Page() {
  return (
    <Image
      src="/profile.png"
      alt="Profile"
      width={500}
      height={500}
    />
  )
}

next/font/google trong _app.tsx

Vì Pages Router không có root layout, áp font toàn cục trong _app.tsx:

// pages/_app.tsx
import { Geist } from 'next/font/google'
import type { AppProps } from 'next/app'

const geist = Geist({ subsets: ['latin'] })

export default function MyApp({ Component, pageProps }: AppProps) {
  return (
    <main className={geist.className}>
      <Component {...pageProps} />
    </main>
  )
}

Local fonts

import localFont from 'next/font/local'

const myFont = localFont({
  src: './my-font.woff2',
})
Khác với App Router

Pages Router dùng <Head> từ next/head để inject tag vào <head>. Không có Metadata API — SEO phải tự viết <title> và <meta> tags.

import Head from 'next/head'

export default function Page() {
  return (
    <>
      <Head>
        <title>Trang chủ</title>
        <meta name="description" content="Mô tả trang" />
      </Head>
      <main>...</main>
    </>
  )
}
Chương 16

CSS

Pages Router hỗ trợ CSS Modules, Global CSS, Tailwind CSS, Sass, và CSS-in-JS — giống App Router, nhưng có 1 điểm khác quan trọng.

Global CSS

Hạn chế

Global CSS chỉ được import trong pages/_app.tsx. Import ở bất kỳ file nào khác sẽ bị Next.js báo lỗi. Đây là khác biệt lớn với App Router — nơi global CSS có thể import ở bất kỳ layout/page nào.

// pages/_app.tsx — CHỈ Ở ĐÂY
import '../styles/globals.css'

export default function MyApp({ Component, pageProps }) {
  return <Component {...pageProps} />
}

CSS Modules

Có thể dùng ở bất kỳ component nào:

// components/Button.module.css
// .button { background: red; }

import styles from './Button.module.css'

export default function Button() {
  return <button className={styles.button}>Click</button>
}

Tailwind CSS

Config content trong tailwind.config.js để Tailwind scan file trong pages/ và components/:

// tailwind.config.js
module.exports = {
  content: [
    './pages/**/*.{js,ts,jsx,tsx}',
    './components/**/*.{js,ts,jsx,tsx}',
  ],
  // ...
}
Chương 17

Deploying

Pages Router deploy giống App Router — Node.js server, Docker, static export, hoặc adapter.

Node.js

npm run build
npm run start  # Khởi chạy server production

Static export

Pages Router có thể export hoàn toàn thành static HTML nếu không dùng SSR:

// next.config.js
module.exports = {
  output: 'export',
}
Không hỗ trợ khi static export

API Routes, getServerSideProps, ISR, Image Optimization mặc định (cần custom loader), Middleware/Proxy. Tất cả phải chuyển sang client-side hoặc loại bỏ.

Docker

Giống App Router — dùng output: 'standalone' để tạo image tối thiểu:

module.exports = {
  output: 'standalone',
}
Chương 18

Upgrading & Migration

Nâng cấp Next.js

# Dùng codemod tự động
npx @next/codemod@canary upgrade latest

# Hoặc thủ công
npm i next@latest react@latest react-dom@latest

Breaking changes lớn với Pages Router

  • Next.js 16: Turbopack thành default bundler cho cả next dev và next build. Middleware renamed → proxy. next build không tự chạy linter nữa.
  • Next.js 15: fetch không cache mặc định. NextRequest.geo và .ip bị remove. @next/font → next/font.
  • Next.js 13: next/image mới (breaking), next/link không còn cần thẻ <a> con.

Migration sang App Router

Team Next.js cung cấp guide migrate tăng dần. Các điểm chính cần đổi:

Migrate tăng dần

App Router và Pages Router có thể cùng tồn tại trong cùng 1 dự án. Bạn có thể migrate từng page một — không cần rewrite toàn bộ. Route trùng tên giữa app/ và pages/ sẽ ưu tiên app/.

Codemods hữu ích

# Rename next/image → next/legacy/image (giữ behavior cũ)
npx @next/codemod next-image-to-legacy-image .

# Remove <a> tags trong <Link> components
npx @next/codemod new-link .

# Migrate @next/font → next/font
npx @next/codemod built-in-next-font .
