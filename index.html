Next.js Getting Started

Tổng hợp đầy đủ tiếng Việt toàn bộ phần Getting Started của tài liệu Next.js chính thức — từ cài đặt, cấu trúc dự án, routing, data fetching, đến deploy và nâng cấp. Cập nhật cho Next.js 16 với App Router.

Chương 01

Cài đặt

Next.js là một React framework cho phép xây dựng ứng dụng web full-stack. Bạn viết giao diện bằng React Components, còn Next.js lo phần tối ưu, bundler, compiler, và các tính năng như routing, data fetching, caching.

Quick start

Cách nhanh nhất để tạo app mới là dùng CLI create-next-app:

# pnpm (khuyến nghị)
pnpm create next-app@latest my-app --yes
cd my-app
pnpm dev

# npm
npx create-next-app@latest my-app --yes
cd my-app
npm run dev

Cờ --yes bỏ qua các câu hỏi và dùng cấu hình mặc định: TypeScript, Tailwind CSS, ESLint, App Router, Turbopack, với import alias @/*, và kèm file AGENTS.md (cùng CLAUDE.md) để hướng dẫn các coding agent viết code Next.js cập nhật.

Yêu cầu hệ thống

  • Node.js: tối thiểu 20.9
  • OS: macOS, Windows (gồm WSL), Linux
  • Trình duyệt hỗ trợ: Chrome 111+, Edge 111+, Firefox 111+, Safari 16.4+

Cài đặt thủ công

pnpm i next@latest react@latest react-dom@latest

Thêm scripts vào package.json:

{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "lint": "eslint",
    "lint:fix": "eslint --fix"
  }
}
Lưu ý

Turbopack là bundler mặc định từ Next.js 16. Nếu muốn dùng Webpack, chạy next dev --webpack hoặc next build --webpack.

Tạo thư mục app

Next.js dùng file-system routing — routes được xác định bởi cấu trúc file/folder. Tạo thư mục app với layout.tsx (bắt buộc, phải chứa <html> và <body>):

// app/layout.tsx
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
// app/page.tsx
export default function Page() {
  return <h1>Hello, Next.js!</h1>
}

TypeScript, ESLint & Path Aliases

Next.js hỗ trợ TypeScript sẵn. Đổi đuôi file thành .tsx và chạy next dev — Next.js sẽ tự cài dependencies và tạo tsconfig.json. Về linter, bạn có thể dùng ESLint hoặc Biome. Cấu hình path aliases trong tsconfig.json:

{
  "compilerOptions": {
    "baseUrl": "src/",
    "paths": {
      "@/components/*": ["components/*"]
    }
  }
}
Thay đổi

Từ Next.js 16, next build không tự chạy linter nữa. Hãy chạy linter qua NPM scripts.

Chương 02

Cấu trúc dự án

Next.js không ép buộc cách tổ chức code, nhưng có một số quy ước đặc biệt. Trong thư mục app, folder lồng nhau sẽ định nghĩa cấu trúc routes. Route chỉ public khi có file page.js hoặc route.js — nghĩa là bạn có thể colocate các file hỗ trợ (components, utils, styles) ngay trong route segment mà không sợ bị route.

Top-level folders

app/ # App Router — routes, layouts, pages pages/ # Pages Router (tùy chọn, tương thích ngược) public/ # Static assets (ảnh, font, favicon...) src/ # Tùy chọn — tách code khỏi config

Các file đặc biệt trong app/

FileVai trò
layout.jsUI chia sẻ giữa nhiều page — giữ state khi navigate
page.jsUI riêng cho 1 route — mở route ra public
loading.jsUI loading khi Suspense đang chờ
error.jsError boundary cho route segment
not-found.jsUI cho 404
route.jsAPI endpoint (Route Handler)
template.jsGiống layout nhưng tạo instance mới mỗi lần navigate
default.jsFallback cho parallel routes

Quy ước đặt tên folder

[folder] [...folder] [[...folder]] (folder) _folder @folder
  • [slug] — Dynamic segment (1 tham số)
  • [...slug] — Catch-all (nhiều tham số)
  • [[...slug]] — Optional catch-all
  • (marketing) — Route group, tổ chức routes mà không ảnh hưởng URL
  • _components — Private folder, không được route
  • @analytics — Named slot cho parallel routes
Mẹo tổ chức

Lưu code dùng chung ở root app/, và code chuyên biệt trong chính route segment sử dụng nó. Dùng route groups (auth), (dashboard) để áp layout khác nhau cho các nhóm route.

Chương 03

Layouts & Pages

Một page là UI render tại một route cụ thể. Một layout là UI chia sẻ giữa nhiều page — khi navigate, layout vẫn giữ state và không re-render.

Tạo page

// app/page.tsx — route "/"
export default function Page() {
  return <h1>Hello, Home page!</h1>
}

Tạo layout

// app/dashboard/layout.tsx
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <section>
      <nav>Dashboard Nav</nav>
      <main>{children}</main>
    </section>
  )
}

Nested routes

Lồng folder để tạo nested routes. Ví dụ cho /blog/my-post:

app/ blog/ page.tsx # /blog [slug]/ page.tsx # /blog/:slug

Dynamic Segments

// app/blog/[slug]/page.tsx
export default async function BlogPostPage({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = await getPost(slug)
  return <h1>{post.title}</h1>
}
Quan trọng — Next.js 15+

params và searchParams là Promise — phải await trước khi dùng. Đây là thay đổi lớn so với Next.js 14.

searchParams

export default async function Page({
  searchParams,
}: {
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  const filters = (await searchParams).filters
}

Dùng searchParams sẽ opt page vào dynamic rendering vì cần request thực tế để đọc tham số.

Chương 04

Linking & Navigating

Next.js có 4 cơ chế tối ưu điều hướng: Prefetching, Prerendering, Streaming, và Client-side transitions.

<Link> component

import Link from 'next/link'

export default function Nav() {
  return (
    <nav>
      <Link href="/">Home</Link>
      <Link href="/blog">Blog</Link>
    </nav>
  )
}

Prefetching

Next.js tự động prefetch các route linked bằng <Link> khi chúng vào viewport. Kết quả: khi user click, dữ liệu đã sẵn sàng client-side → chuyển trang ngay lập tức.

  • Static route: prefetch toàn bộ route
  • Dynamic route: skip prefetch, hoặc prefetch 1 phần nếu có loading.tsx

Hover-based prefetching

Để giảm bandwidth, bạn có thể chỉ prefetch khi user hover:

'use client'
import Link from 'next/link'
import { useState } from 'react'

function HoverPrefetchLink({ href, children }) {
  const [active, setActive] = useState(false)
  return (
    <Link
      href={href}
      prefetch={active ? null : false}
      onMouseEnter={() => setActive(true)}
    >
      {children}
    </Link>
  )
}

Streaming với loading.tsx

Để cải thiện UX cho dynamic routes, tạo loading.tsx trong route folder. Nó cho phép partial prefetching, trigger navigation ngay, và hiển thị UI loading.

Programmatic navigation

'use client'
import { useRouter } from 'next/navigation'

export default function Component() {
  const router = useRouter()
  return <button onClick={() => router.push('/dashboard')}>Go</button>
}
Chương 05

Images

Component <Image> của Next.js mở rộng <img> với các tính năng: size optimization (WebP/AVIF), visual stability (chống layout shift), lazy loading, và on-demand resizing kể cả với ảnh remote.

Sử dụng cơ bản

import Image from 'next/image'

export default function Page() {
  return (
    <Image
      src="/profile.png"
      alt="Picture of the author"
      width={500}
      height={500}
    />
  )
}

Ảnh trong public/ được reference qua base URL /. Nếu import static, Next.js tự xác định width và height để tránh Cumulative Layout Shift.

Remote images

Với ảnh từ URL bên ngoài, cần khai báo remotePatterns trong next.config.ts để tránh abuse:

import { NextConfig } from 'next'

const config: NextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 's3.amazonaws.com',
        pathname: '/my-bucket/**',
      },
    ],
  },
}
export default config
Chương 06

Fonts

Module next/font tự động tối ưu fonts, loại bỏ network requests ra bên ngoài (tự host), và chống layout shift. Hỗ trợ cả Google Fonts và local fonts.

Google Fonts

import { Geist } from 'next/font/google'

const geist = Geist({ subsets: ['latin'] })

export default function Layout({ children }) {
  return (
    <html lang="en" className={geist.className}>
      <body>{children}</body>
    </html>
  )
}
Khuyến nghị

Dùng variable fonts cho hiệu năng tốt nhất. Nếu không, phải chỉ định weight cụ thể.

Local fonts

import localFont from 'next/font/local'

const myFont = localFont({
  src: [
    { path: './Roboto-Regular.woff2', weight: '400', style: 'normal' },
    { path: './Roboto-Bold.woff2', weight: '700', style: 'normal' },
  ],
})

Dùng nhiều font — CSS variables

const inter = Inter({ variable: '--font-inter', subsets: ['latin'] })
const roboto_mono = Roboto_Mono({ variable: '--font-roboto-mono', subsets: ['latin'] })

// Dùng: className={`${inter.variable} ${roboto_mono.variable}`}
Chương 07

CSS

Next.js hỗ trợ nhiều cách styling: Tailwind CSS (mặc định), CSS Modules, Global CSS, Sass, CSS-in-JS.

Tailwind CSS

export default function Page() {
  return (
    <main className="flex min-h-screen flex-col items-center justify-between p-24">
      <h1 className="text-4xl font-bold">Welcome to Next.js!</h1>
    </main>
  )
}

CSS Modules

CSS Modules scope tên class tự động, tránh xung đột. Dùng extension .module.css:

import styles from './blog.module.css'

export default function Page() {
  return <main className={styles.blog}></main>
}

Global CSS

Import global stylesheet trong root layout. Ordering CSS theo thứ tự import. Ví dụ với Bootstrap:

import 'bootstrap/dist/css/bootstrap.css'

export default function RootLayout({ children }) {
  return (
    <html>
      <body className="container">{children}</body>
    </html>
  )
}
Production build

Trong next build, toàn bộ CSS được concat thành nhiều file minified + code-split để chỉ load CSS cần thiết cho từng route. Luôn kiểm tra build thực tế để verify thứ tự CSS.

Chương 08

Server & Client Components

Mặc định, layouts và pages là Server Components — render trên server, có thể fetch data trực tiếp, và stream về client. Khi cần tương tác hoặc browser APIs, chuyển sang Client Components.

Khi nào dùng Client Components?

  • State & event handlers (onClick, onChange)
  • Lifecycle logic (useEffect)
  • Browser-only APIs (localStorage, window, Geolocation...)
  • Custom hooks

Khi nào dùng Server Components?

  • Fetch data từ DB/API gần nguồn dữ liệu
  • Dùng API keys, tokens, secrets mà không expose ra client
  • Giảm JavaScript gửi xuống browser
  • Cải thiện First Contentful Paint (FCP), stream UI progressive

Directive 'use client'

'use client'
import { useState } from 'react'

export default function LikeButton({ likes }: { likes: number }) {
  const [count, setCount] = useState(likes)
  return <button onClick={() => setCount(count + 1)}>{count}</button>
}

Composition pattern

Server Component fetch data → truyền xuống Client Component làm prop:

// Server Component
import LikeButton from '@/app/ui/like-button'
import { getPost } from '@/lib/data'

export default async function Page({ params }) {
  const { id } = await params
  const post = await getPost(id)
  return (
    <main>
      <h1>{post.title}</h1>
      <LikeButton likes={post.likes} />
    </main>
  )
}

Server Components → Client Components as children

Pattern phổ biến: dùng children để nest Server Component bên trong Client Component:

// Modal là Client Component
'use client'
export default function Modal({ children }) {
  return <div>{children}</div>
}

// Page (Server) truyền Cart (Server) vào Modal (Client)
export default function Page() {
  return <Modal><Cart /></Modal>
}
RSC Payload

Server Components render thành một format đặc biệt gọi là RSC Payload — biểu diễn nhị phân compact của React tree. Browser dùng nó kết hợp với HTML để hydrate Client Components.

Chương 09

Fetching Data

Trong Server Components, bạn có thể fetch dữ liệu bằng bất kỳ async I/O nào: fetch, ORM, database client, filesystem...

Fetch API

export default async function Page() {
  const data = await fetch('https://api.vercel.app/blog')
  const posts = await data.json()
  return (
    <ul>
      {posts.map((post) => <li key={post.id}>{post.title}</li>)}
    </ul>
  )
}
Thay đổi quan trọng

Từ Next.js 15, fetch requests không còn cache mặc định. Dùng use cache directive hoặc cache: 'force-cache' để opt-in caching.

Database queries với ORM

import { db, posts } from '@/lib/db'

export default async function Page() {
  const allPosts = await db.select().from(posts)
  return <ul>{allPosts.map(/* ... */)}</ul>
}

Credentials và query logic không bị gửi xuống client bundle.

Streaming với Suspense

import { Suspense } from 'react'
import Posts from '@/app/ui/posts'

export default function Page() {
  // KHÔNG await — truyền promise xuống
  const posts = getPosts()
  return (
    <Suspense fallback={<div>Loading...</div>}>
      <Posts posts={posts} />
    </Suspense>
  )
}
'use client'
import { use } from 'react'

export default function Posts({ posts }) {
  const allPosts = use(posts) // đọc promise ở client
  return <ul>{allPosts.map(/* ... */)}</ul>
}

Parallel fetching

Requests tuần tự block nhau. Dùng Promise.all để parallel:

const [artist, albums] = await Promise.all([
  getArtist(username),
  getAlbums(username),
])
Chương 10

Caching & Revalidating

Directive 'use cache' cache giá trị trả về của async function/component. Áp dụng ở 2 cấp: data-level (function fetch data) và UI-level (cả component).

Cache data function

async function getProducts() {
  'use cache'
  const res = await fetch('https://api.example.com/products')
  return res.json()
}

Cache toàn bộ component

async function BlogPosts() {
  'use cache'
  const posts = await getPosts()
  return <ul>{/* ... */}</ul>
}

Arguments và closed-over values tự động trở thành cache key, cho phép content được cache có tham số riêng cho từng input.

Revalidation

Chiến lượcCách dùng
Time-basedcacheLife() với thời gian cụ thể
Tag-basedcacheTag('posts') + revalidateTag('posts')
Path-basedrevalidatePath('/blog')
On-demandGọi từ Server Action hoặc Route Handler
Partial Prerendering

Khi bật Cache Components, Next.js prerender routes thành static shell và chỉ defer các phần dynamic sang request-time — combine lợi ích của static và dynamic.

Chương 11

Updating Data

Update data trong Next.js qua React Server Functions. Đây là async functions chạy trên server, có thể gọi từ client qua network request. Khi dùng trong context form/mutation, gọi là Server Actions.

Tạo Server Function

Thêm directive 'use server' ở đầu file hoặc đầu function body:

// app/actions.ts
'use server'

export async function createPost(formData: FormData) {
  const title = formData.get('title')
  const content = formData.get('content')
  // Update data
  // Revalidate cache
}

Dùng trong form

import { createPost } from '@/app/actions'

export function Form() {
  return (
    <form action={createPost}>
      <input name="title" />
      <input name="content" />
      <button type="submit">Create</button>
    </form>
  )
}
Progressive Enhancement

Server Components mặc định hỗ trợ progressive enhancement — form vẫn submit được kể cả khi JavaScript chưa load xong hoặc bị tắt.

Gọi từ event handler

'use client'
import { incrementLike } from './actions'

export default function LikeButton({ initialLikes }) {
  const [likes, setLikes] = useState(initialLikes)
  return (
    <button onClick={async () => {
      const updated = await incrementLike()
      setLikes(updated)
    }}>
      Like ({likes})
    </button>
  )
}

Revalidate sau khi mutate

'use server'
import { revalidatePath } from 'next/cache'
import { auth } from '@/lib/auth'

export async function createPost(formData: FormData) {
  const session = await auth()
  if (!session?.user) throw new Error('Unauthorized')
  
  // ... insert to DB
  revalidatePath('/posts')
}
Bảo mật

Server Functions là public HTTP endpoints — có thể gọi qua POST trực tiếp, không chỉ qua UI. Luôn verify authentication & authorization bên trong mỗi Server Function.

Chương 12

Error Handling

Lỗi chia thành 2 loại: expected errors (validation, failed request) — model như return values; và uncaught exceptions — xử lý bằng error boundaries.

Expected errors — useActionState

'use server'

export async function createPost(prevState, formData) {
  const res = await fetch('/api/posts', { method: 'POST', /* ... */ })
  if (!res.ok) {
    return { message: 'Failed to create post' }
  }
}
'use client'
import { useActionState } from 'react'
import { createPost } from '@/app/actions'

export function Form() {
  const [state, formAction] = useActionState(createPost, { message: '' })
  return (
    <form action={formAction}>
      <input name="title" />
      {state?.message && <p>{state.message}</p>}
      <button>Create</button>
    </form>
  )
}

Uncaught exceptions — error.tsx

Tạo file error.tsx trong route segment (phải là Client Component):

'use client'

export default function Error({
  error,
  reset,
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  return (
    <div>
      <h2>Có lỗi xảy ra!</h2>
      <button onClick={() => reset()}>Thử lại</button>
    </div>
  )
}
Error boundary scope

error.js bao phủ loading.js, not-found.js, page.js, và nested layout.js — nhưng không bao layout.js/template.js cùng segment. Để handle lỗi ở root layout, dùng global-error.js.

404 — notFound() & not-found.tsx

import { notFound } from 'next/navigation'

export default async function Page({ params }) {
  const { slug } = await params
  const post = await getPostBySlug(slug)
  if (!post) notFound()
  return <div>{post.title}</div>
}

Global error — global-error.tsx

Bao toàn bộ app, kể cả root layout. Phải tự define <html> và <body>:

'use client'

export default function GlobalError({ error, reset }) {
  return (
    <html>
      <body>
        <h2>Something went wrong!</h2>
        <button onClick={() => reset()}>Try again</button>
      </body>
    </html>
  )
}
Chương 13

Partial Prerendering

Partial Prerendering (PPR) là chiến lược render kết hợp static và dynamic content trong cùng 1 route. Cải thiện initial page performance mà vẫn hỗ trợ personalized, dynamic data.

Cách hoạt động

  1. Server gửi shell chứa static content → initial load cực nhanh
  2. Shell có các "hole" cho dynamic content
  3. Các hole được stream song song, giảm total load time

Enable PPR

// next.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  experimental: {
    ppr: 'incremental',
  },
}
export default nextConfig
// Opt-in cho từng route
export const experimental_ppr = true

export default function Layout({ children }) {
  return <section>{children}</section>
}

Suspense boundary

Wrap dynamic components trong <Suspense> để defer rendering:

import { Suspense } from 'react'

export default function Page() {
  return (
    <>
      <StaticComponent />
      <Suspense fallback={<Fallback />}>
        <DynamicComponent />
      </Suspense>
    </>
  )
}
Hiệu quả

Đặt Suspense boundary càng gần component cần defer càng tốt. Điều này maximize lượng content trong static shell, và cho phép nhiều dynamic section render song song.

Chương 14

Metadata & OG Images

Next.js có Metadata API để định nghĩa metadata theo 2 cách: Config-based (export từ layout/page) và File-based (file quy ước như favicon.ico, opengraph-image.jpg).

Static metadata

// app/blog/page.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'My Blog',
  description: 'Read my latest posts',
  openGraph: {
    title: 'My Blog',
    images: ['/og.png'],
  },
}

export default function Page() { /* ... */ }

Dynamic metadata

export async function generateMetadata({ params }): Promise<Metadata> {
  const { slug } = await params
  const post = await getPost(slug)
  return {
    title: post.title,
    description: post.excerpt,
  }
}

Favicon

Đặt file favicon.ico vào root của thư mục app/. Next.js tự generate <link rel="icon">.

Static OG image

Đặt file opengraph-image.jpg vào route segment. Ảnh cụ thể hơn sẽ override ảnh ở root:

app/ opengraph-image.jpg # OG mặc định blog/ opengraph-image.jpg # OG cho /blog

Dynamic OG image với ImageResponse

// app/blog/[slug]/opengraph-image.tsx
import { ImageResponse } from 'next/og'
import { getPost } from '@/app/lib/data'

export const size = { width: 1200, height: 630 }
export const contentType = 'image/png'

export default async function Image({ params }) {
  const post = await getPost(params.slug)
  return new ImageResponse(
    (
      <div style={{
        fontSize: 128,
        background: 'white',
        width: '100%',
        height: '100%',
        display: 'flex',
        alignItems: 'center',
        justifyContent: 'center',
      }}>
        {post.title}
      </div>
    )
  )
}
Hạn chế ImageResponse

Dùng @vercel/og + satori + resvg để convert HTML/CSS thành PNG. Chỉ hỗ trợ flexbox và subset của CSS — display: grid KHÔNG hoạt động.

Deploying

Next.js có thể deploy theo 4 cách: Node.js server, Docker container, Static export, hoặc qua Adapter.

Cách deployHỗ trợ tính năng
Node.js serverĐầy đủ
Docker containerĐầy đủ
Static exportHạn chế (không dynamic)
AdaptersTùy adapter

Node.js

# Đảm bảo package.json có "build" và "start"
npm run build
npm run start

Docker

Dùng multi-stage Dockerfile với output: 'standalone' trong next.config.js để tạo image tối thiểu.

Static export

// next.config.ts
const nextConfig = {
  output: 'export',
}
export default nextConfig

Sau next build, thư mục out/ chứa HTML/CSS/JS static — có thể host trên AWS S3, Nginx, Apache... Không hỗ trợ Server Components dynamic, Route Handlers động, v.v.

Adapter API

Next.js có Deployment Adapter API cho phép platforms custom cách build và deploy. Verified adapters chạy full test suite của Next.js. Cloudflare và Netlify đang xây dựng verified adapters; trong thời gian chờ, họ có integrations riêng.

Tối ưu self-host

Từ Next.js 15, không cần cài sharp thủ công — Next.js tự dùng khi chạy next start hoặc standalone mode.

Upgrading

Để nâng cấp lên phiên bản mới nhất, dùng command next upgrade (có từ Next.js 16.1.0):

pnpm next upgrade

# Với phiên bản < 16.1.0
npx @next/codemod@canary upgrade latest

# Thủ công
pnpm i next@latest react@latest react-dom@latest eslint-config-next@latest

Codemod tự động

Codemod là các transformation chạy trên codebase để tự áp dụng thay đổi. Cú pháp:

npx @next/codemod <transform> <path>

# Ví dụ: migrate cookies()/headers() sang async
npx @next/codemod@latest next-async-request-api .

Nâng cấp lên Next.js 16

Codemod v16 xử lý tự động:

  • Update next.config.js dùng cấu hình Turbopack mới
  • Migrate từ next lint sang ESLint CLI
  • Migrate từ convention middleware sang proxy
  • Remove prefix unstable_ khỏi các APIs đã stable
  • Remove experimental_ppr Route Segment Config khỏi pages/layouts
Breaking — Next.js 16

Synchronous access cho cookies(), headers(), draftMode(), params, searchParams đã bị loại bỏ hoàn toàn. Phải dùng await.

Nâng cấp lên Next.js 15

  • React 19: App Router dùng React 19, Pages Router vẫn giữ React trong package.json
  • Async Request APIs: cookies(), headers(), params, searchParams giờ là async
  • Caching: fetch và GET Route Handlers không cache mặc định
  • @next/font: đã xóa, dùng next/font built-in
  • NextRequest.geo/ip: đã bị remove — dùng @vercel/functions hoặc header từ hosting provider

Canary channel

pnpm add next@canary

Các tính năng canary hiện tại: "use cache", cacheLife, cacheTag, dynamicIO, forbidden, unauthorized, forbidden.js, unauthorized.js, authInterrupts.

Typegen

Chạy npx next typegen để generate global type helpers như PageProps<'/blog/[slug]'>, LayoutProps — giúp migrate sang async params type-safe.
